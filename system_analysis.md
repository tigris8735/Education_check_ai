# Системный анализ

## 1. Функциональные требования

### 1.1. Управление пользователями и сессиями
- Веб-доступ через браузер для преподавателей и студентов.
- Регистрация и вход.
- Аутентификация по JWT.
- Роли: `TEACHER`, `STUDENT`, `ADMIN`.
- Выход из системы и обновление токена.

### 1.2. Управление группами
- Преподаватель создаёт группу.
- Добавление/удаление студентов из группы.
- Просмотр списка групп и участников.
- Привязка заданий к группе.

### 1.3. Работа с заданиями и работами
- Создание задания: название, описание, дедлайн, критерии.
- Загрузка работы студентом.
- Хранение текста работы и метаданных.
- Статусы работы: `DRAFT`, `SUBMITTED`, `AI_CHECKED`, `REVIEWED`.

### 1.4. AI-проверка
- Отправка текста работы в AI Check Service.
- Формирование промпта по критериям задания.
- Получение оценки и комментариев.
- Сохранение результата AI-проверки.
- Возможность ручной корректировки преподавателем.

### 1.5. Обратная связь
- Преподаватель видит AI-разбор и выставляет итоговую оценку.
- Студент видит комментарии, оценку и статус.
- История проверок по работе.

## 2. Нефункциональные требования

### 2.1. Производительность
- Загрузка страницы — < 2 секунд.
- AI-проверка одной работы — < 10 секунд.
- API-ответы микросервисов — < 500 мс без учёта AI.

### 2.2. Архитектурные особенности
- Микросервисная архитектура.
- API Gateway для маршрутизации.
- Отдельная БД Neon (PostgreSQL).
- Деплой на Render: статический сайт + web services.
- Стек: Python, JavaScript, CSS, HTML.

### 2.3. Надёжность и безопасность
- JWT-авторизация.
- Разграничение доступа по ролям.
- Валидация входных данных.
- Логирование ошибок.
- Обработка недоступности AI-сервиса.

## 3. Технологический стек

### 3.1. Frontend
- HTML, CSS, JavaScript.
- Fetch API для запросов к API Gateway.
- Адаптивная вёрстка без тяжёлых фреймворков.

### 3.2. Backend
- Python 3.10+.
- FastAPI для микросервисов.
- Uvicorn как ASGI-сервер.
- Pydantic для схем данных.

### 3.3. База данных
- Neon PostgreSQL.
- Отдельные схемы/таблицы для сервисов.
- Миграции через Alembic или SQL-скрипты.

### 3.4. AI-интеграция
- AI Check Service вызывает LLM по HTTP API.
- OpenAI-совместимый формат запроса.
- Промпты формируются на основе критериев задания.

### 3.5. Деплой
- Render Static Site для frontend.
- Render Web Services для Python-микросервисов.
- Neon — облачная БД.
- Переменные окружения для секретов.

## 4. Ограничения системы

### 4.1. Технические ограничения
- Качество AI-проверки зависит от выбранной LLM.
- Neon может иметь задержку при холодном старте.
- Render может ограничивать ресурсы на бесплатных тарифах.
- Нет поддержки офлайн-режима.

### 4.2. Функциональные ограничения
- Поддержка текстовых работ; сканы без OCR не обрабатываются.
- Нет полноценного видеоконференц-модуля.
- Нет мобильного приложения — только веб.
